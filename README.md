# Avito → LPTracker CRM

Последовательная, возобновляемая система:

```text
Google Sheets / XLSX / CSV
          ↓
видимый Playwright Chromium или установленный Chrome Stable с постоянным профилем
          ↓
DOM → OCR изображения (если номер не текстом)
          ↓
нормализация +7XXXXXXXXXX и дедупликация
          ↓
LPTracker: контакт/лид + поле «Тег+ для новых с Ав и Ян»
          ↓
статус, ошибка, Run ID и продолжение с нужной строки
```

Система не содержит обхода CAPTCHA, подмены отпечатка браузера, ротации прокси
или других механизмов обхода защиты. Работа идёт по одному объявлению, с
плановыми паузами и без искусственного ограничения размера очереди. Если Avito требует проверку, открытый браузер ставит
очередь на паузу, запускает каскад MAX/email/Telegram-уведомлений и автоматически
продолжает работу после ручного решения.

## Что реализовано

- Google Sheets, локальный `.xlsx` и `.csv` как взаимозаменяемые очереди;
- автоматическое добавление служебных колонок без удаления исходных данных;
- видимый Playwright Chromium/Chrome Stable либо обычный пользовательский Chrome
  через локальное Manifest V3 расширение без WebDriver и remote debugging;
- необязательный вход в Avito: профиль одинаково сохраняет вход, выход или гостевой режим;
- извлечение номера из `tel:`/DOM, затем OCR нескольких вариантов изображения;
- строгая нормализация российских номеров в `+7XXXXXXXXXX`;
- автоматический поиск проекта, поля и допустимой категории в LPTracker;
- проверка контакта по телефону до создания лида;
- запись URL объявления в комментарии продажи каждого созданного лида;
- ограниченная синхронизация только активных новых лидов и один управляемый
  второй лид для шага `Автоответчики`;
- часовой префикс в имени лида и безопасная фоновая передача при совпадении шага
  `⚙️ Лид с робота` с одним из двух утверждённых тегов сбора после распознавания
  продиктованного номера:
  замена телефона, тег, `Дата шага` через 48 часов и только затем `Новый лид`;
- защита местного времени: создание лидов только в окне 10:00–19:45 по городу
  из листа `План загрузки`;
- идемпотентность по объявлению, телефону и локальному SQLite-журналу;
- команды `capture`, `sync-crm`, `run`, `stop`, `status`, `doctor`;
- явный `--live` для любых записей в CRM;
- удалённый Google Sheets-пульт с целью по лидам, жёстким пределом просмотра, уникальными ID команд, STOP, историей и аналитикой;
- фоновый диспетчер Windows с восстановлением незавершённой команды после сбоя;
- мягкая остановка, необязательная цель успешных лидов (`0` = вся очередь),
  автоматические повторные круги и аварийный выключатель;
- каскад MAX/Email/Telegram при капче: сразу, напоминание и эскалация резервному человеку;
- одно итоговое уведомление о завершении со статистикой без лишнего сообщения после решения капчи;
- независимый выбор основных и резервных получателей итогов для MAX, email и Telegram;
- диагностические скриншоты только при ошибках и без попадания в Git.

## Быстрый запуск на Windows

Требования: Windows 10/11, Python 3.11+, Git и Tesseract OCR.

```powershell
git clone https://github.com/eduard-zheleznov/-AV-crm.git avito-crm
cd avito-crm
git switch feature/google-sheets-gui
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\install.ps1
```

Установщик создаст `.venv`, установит зависимости и Chromium, затем создаст
локальный `.env` и `queue-template.xlsx`. Реальные логин, пароль и JSON
сервисного аккаунта Google должны находиться только на удалённом компьютере.

Подробная инструкция: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Запуск без терминала

`install.ps1` создаёт на рабочем столе ярлык **«Avito в CRM»**. В GUI выбираются
Google-таблица, лист, JSON service account и лимит. Кнопка **«Открыть профиль»**
открывает тот же Playwright-браузер, который используется при обработке: можно войти,
выйти из Avito или оставить гостевой режим. Там же есть проверка доступа, живой
журнал и мягкая остановка.

Подробнее: [docs/GOOGLE_GUI.md](docs/GOOGLE_GUI.md).

Если Avito запрашивает проверку сразу после запуска Playwright-браузера, используйте
режим обычного Chrome: [docs/CHROME_EXTENSION.md](docs/CHROME_EXTENSION.md). Капча
в этом режиме решается оператором вручную в той же вкладке; программа её не обходит.

Для запуска сотрудником без доступа к удалённому компьютеру установите фоновый
Google Sheets-пульт: [docs/REMOTE_CONTROL.md](docs/REMOTE_CONTROL.md). После этого
сотрудник добавляет ссылки, задаёт лимит на листе `Управление` и ставит галочку
**ЗАПУСТИТЬ В CRM**; статус и последняя связь видны там же, а сводка — на листе
`Аналитика`.

Настройка уведомлений: [docs/MAX.md](docs/MAX.md), [docs/EMAIL.md](docs/EMAIL.md)
и [docs/TELEGRAM.md](docs/TELEGRAM.md).

## Безопасная первая проверка

Самый простой вариант — интерактивный мастер. Он сначала показывает проекты
CRM, затем держит браузер открытым для сверки одного номера и только после
отдельного подтверждения создаёт ровно один лид:

```powershell
.\scripts\first-test.ps1 -Source xlsx -File ".\queue-template.xlsx" -Sheet "Лист1"
```

Первый тест через Excel проще: он не требует сервисного аккаунта Google.
После успешной проверки тот же мастер можно запустить с `-Source google`.

Подробно, с ожидаемым результатом каждого шага:
[docs/FIRST_TEST.md](docs/FIRST_TEST.md).

Те же действия вручную:

```powershell
# 1. Проверка OCR, Chromium, очереди и CRM без изменений CRM
.\scripts\doctor.ps1 -Source google -OnlineCrm

# 2. Получить один номер, ничего не создавая в CRM
.\scripts\run.ps1 -Source google -Limit 1 -Mode capture

# 3. После визуальной проверки телефона создать ровно один лид
.\scripts\run.ps1 -Source google -Limit 1 -Mode crm -Live

# 4. Полный поток на заданное количество новых лидов
.\scripts\run.ps1 -Source google -Limit 10 -Mode full -Live
```

Для локального Excel:

```powershell
.\scripts\run.ps1 -Source xlsx -File "C:\queues\avito.xlsx" -Sheet "Лист1" -Limit 10 -Live
```

Остановить после текущего безопасного шага:

```powershell
.\scripts\stop.ps1
.\scripts\status.ps1
```

Новые объявления всегда идут раньше старых ошибок. Первая сессия получения
номера содержит один клик и один клик после перезагрузки. Если оба неуспешны,
единственный финальный клик разрешается не раньше чем через 30 минут. После него
строка становится терминальной.

## Статусы очереди

| Статус | Значение | Повтор по умолчанию |
|---|---|---:|
| `processing` | шаг начат; после аварии можно продолжить | да |
| `retry_phone` | кнопка была, но номер не открылся; ожидает следующего круга | да, автоматически |
| `retry_technical` | временная техническая ошибка; ожидает следующего круга | да, автоматически |
| `captured` | номер распознан, CRM ещё не изменялась | для CRM |
| `crm_monitoring` | первый лид создан; ожидается результат первого звонка | только проверка CRM |
| `crm_comment_pending` | второй лид создан; ссылка Avito ожидает дозаписи в комментарий | только комментарий |
| `crm_monitor_expired` | CRM не завершила первый звонок за 24 часа | нет |
| `done` | цикл загрузчика завершён | нет |
| `duplicate` | контакт/лид уже существует | нет |
| `inactive` | Avito явно сообщает, что объявление снято, закрыто, удалено или заблокировано | нет |
| `unavailable` | страница загрузилась, но кнопки телефона нет | нет |
| `no_phone` | кнопка была, но номер не открылся после всех попыток | нет |
| `error` | техническая ошибка сохранилась после всех попыток | нет |
| `manual_required` | Avito требует ручного действия | после решения — «Повторить строки после капчи (обычно выкл.)» |
| `repeat_pending` | первый лид перешёл в `Автоответчики`; запланирован второй лид | да |
| `repeat_retry_phone` | повторный номер не открылся; остались попытки | да, автоматически |
| `repeat_retry_technical` | временный технический сбой повторного лида | да, автоматически |
| `repeat_exhausted` | три повторных открытия не дали номер | нет |
| `recreate_pending` | восстановление строки, которую старая версия уже успела удалить до обновления | да, только аварийное восстановление |
| `invalid` | ссылка не относится к объявлению Avito | нет |

`-Limit` в полном live-режиме означает необязательную цель по количеству
**созданных лидов**, а не число просмотренных строк. Значение `0` обрабатывает
все доступные строки без верхнего предела. Дубликаты, неактивные объявления, отсутствующие кнопки
и неоткрытые номера лимит не расходуют и не считаются техническими ошибками.

## Аналитика запусков

Удалённый пульт автоматически создаёт лист `Аналитика`. В нём выбирается период
7, 30, 90 или 365 дней, показываются текущий и предыдущий сопоставимый период,
конверсия, количество обработанных ссылок, открытых номеров, созданных лидов,
строк на шаге `Недозвон`,
нормальных недоступных результатов и настоящих технических ошибок. Источником
служит лист `История запусков`; вручную пересчитывать таблицу не нужно.

## Конфигурация

Все параметры документированы в [.env.example](.env.example). Обязательные:

- `LPTRACKER_LOGIN`, `LPTRACKER_PASSWORD`;
- `LPTRACKER_PROJECT_ID` (предпочтительно) либо точное `LPTRACKER_PROJECT_NAME`;
- `GOOGLE_CREDENTIALS_FILE`, `GOOGLE_SPREADSHEET_ID`, `GOOGLE_WORKSHEET` для
  Google Sheets;
- `TESSERACT_CMD`, если `tesseract.exe` отсутствует в `PATH`.

Целевое поле и значение уже стоят в безопасных значениях по умолчанию:

- `Тег+ для новых с Ав и Ян`;
- `Сбор № лпр (Ав, ремонт кв. под ключ)`.

Перед созданием первого лида система проверяет, что проект, поле и категория
существуют. При опечатке запуск завершится до изменения CRM.

## Повторные лиды

После первого созданного лида строка получает `Попытка завода в CRM = 1`.
Проверяются только строки со статусом `crm_monitoring`; исторические `done` не
читаются из LPTracker. Шаги `Новый лид` и `⚙️ Лид с робота` остаются под
контролем, `Автоответчики` разрешает повтор, а любой другой результат завершает
цикл загрузчика. Контроль автоматически прекращается через 24 часа.

Для повтора программа получает свежий временный номер и создаёт отдельный лид на
шаге `Повторный лид`, даже если номер совпал. Второй ID хранится в `Повторный CRM
ID`, счётчик атомарно становится `2`, и строка навсегда исключается из новых
повторов. Таким образом, по одному Avito ID возможно не более двух CRM-лидов.

Правило удаления `Недозвон` из-за задержки первого звонка больше 10 минут
отключено. Вместо него до открытия номера и непосредственно перед записью в CRM
проверяется местное окно 10:00–19:45. URL, приоритет и `Δ к МСК` берутся из листа
`План загрузки`; если URL или смещение отсутствуют, live-запись блокируется.

Для каждого из двух возможных звонков получение номера имеет отдельный предел:
два клика в первой сессии и один отложенный финальный клик. После неудачи
повторного цикла устанавливается `repeat_exhausted`.
Обычные дубликаты первого лида по-прежнему безопасно пропускаются политикой
`CRM_DUPLICATE_POLICY=skip`.

Следующий этап после звонка робота настраивается отдельно и по умолчанию выключен:
[docs/ROBOT_HANDOFF.md](docs/ROBOT_HANDOFF.md).
