# MAX-уведомления о капче

MAX — основной канал для срочных уведомлений сотрудников. Порядок доставки в программе:
MAX → Email → Telegram. Если один канал не отвечает, он отключается до конца текущего запуска,
а остальные продолжают работать.

## Что потребуется

1. Верифицированный профиль организации, ИП или самозанятого в MAX для бизнеса.
2. Созданный и прошедший модерацию чат-бот.
3. Токен бота из раздела **Чат-боты → Перейти → Расширенные настройки → Настроить**.
4. Каждый сотрудник открывает бота в MAX и нажимает **«Начать»**.

Токен нельзя пересылать в чаты или добавлять в Git. Он вводится только локально в программе.

## Настройка в программе

1. Откройте ярлык **«Avito в CRM»**.
2. В строке **«Капча и уведомления»** нажмите **«Настроить MAX»**.
3. Вставьте токен в скрытое поле **«Токен MAX-бота»**.
4. После того как сотрудники нажали «Начать», нажмите **«Найти ID»**.
5. Скопируйте найденные значения вида `user:123` в поле **«Основные ID»**.
6. Подстраховывающего сотрудника добавьте в **«Резервные ID»**.
7. Нажмите **«Отправить тест»**. В журнале должно появиться
   `OK: тестовое MAX-сообщение доставлено`.

Для группового чата используется формат `chat:456`. Бот должен быть добавлен в группу и иметь
необходимые права. Несколько получателей указываются через запятую.

Если у бота уже настроен Webhook, тестовый поиск через Long Polling может быть недоступен.
В таком случае ID берётся из события Webhook и вставляется вручную; отправка уведомлений
продолжает работать независимо от способа получения ID.

## Каскад

При капче программа:

1. сразу пишет основным получателям MAX;
2. дублирует уведомление в настроенные резервные каналы;
3. напоминает через заданные интервалы;
4. последнее напоминание отправляет также резервным сотрудникам;
5. после решения сообщает о продолжении работы.

Используется официальный адрес `https://platform-api2.max.ru`, рекомендованный MAX для перехода
до 19 июля 2026 года. API использует TLS-сертификат Минцифры, поэтому программа добавляет
официальный `Russian Trusted Root CA` только в изолированный TLS-контекст MAX. Системное
хранилище Windows не изменяется, а проверка TLS не отключается.

Если в журнале остаётся `не удалось подключиться к platform-api2.max.ru:443`, проверьте на
удалённом компьютере:

```powershell
Test-NetConnection platform-api2.max.ru -Port 443
```

Значение `TcpTestSucceeded : False` означает блокировку доступа со стороны сети/хостинга, а не
ошибку токена.
