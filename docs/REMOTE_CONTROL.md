# Удалённый пульт в Google Sheets

## Что меняется

После одноразовой установки сотруднику не нужен доступ к удалённому Windows-компьютеру
для обычного запуска. В той же Google-таблице автоматически появляются три листа:

- **`Управление`** — цель, предел просмотра, лист очереди, запуск,
  мягкая остановка, прогресс и
  последняя связь с компьютером;
- **`История запусков`** — журнал команд, итогов и технических метрик;
- **`Аналитика`** — табло за 7, 30, 90 или 365 дней с динамикой и сравнением
  с предыдущим периодом.

Пульт каждые 20 секунд читает таблицу исходящим HTTPS-запросом. Входящие порты,
отдельный сайт, Apps Script и передача паролей сотруднику не нужны. JSON Google,
LPTracker, MAX, email и Telegram остаются только на удалённом компьютере.
Перед каждой новой командой worker заново читает `.env`, поэтому
изменённые в GUI основные и резервные получатели применяются без
выхода из Windows.

## Установка и безопасное обновление на удалённом компьютере

Для первой установки выполните:

```powershell
Set-Location C:\avito-crm
git fetch origin
git switch fix/unbounded-processing-no-answer
git pull --ff-only
Set-ExecutionPolicy -Scope Process Bypass -Force
.\scripts\install.ps1
.\scripts\install-remote-control.ps1
```

Для следующих обновлений достаточно `git pull --ff-only` и
`.\scripts\install.ps1`: установщик сам обнаружит существующий удалённый пульт,
мягко завершит активную строку, обновит задачу Windows и запустит её уже на новой
версии. Профиль Avito, `.env`, очередь и история при этом сохраняются.

Установка пульта:

1. проверяет существующие настройки Google;
2. создаёт и оформляет листы `Управление`, `История запусков` и `Аналитика`;
3. регистрирует задачу Windows **Avito CRM Remote Control**;
4. сразу запускает фоновый диспетчер;
5. включает повторный запуск диспетчера при сбое и автозапуск при входе в Windows.

Положительная **Цель** — это число созданных лидов. **Предел просмотра** —
жёсткая граница числа попыток обработки строк. Значение `0` в поле предела включает
безопасный авторежим: `2 × цель`; если цель тоже `0`, за одну команду просматривается
не более 50 строк.

Проверка на Windows:

```powershell
.\scripts\remote-control-status.ps1 -ShowRecentLog
```

В листе `Управление` поле **Последняя связь с компьютером** должно обновляться
примерно раз в 20 секунд.
Команда также показывает владельцев lock-файлов, текущий этап незавершённой команды
и безопасную выборку диагностических сообщений без телефонов и секретов.
Если оно старше двух минут, не ставьте команду запуска: сначала проверьте удалённый
компьютер и Windows-задачу.

## Как сотрудник запускает обработку

1. Открывает общий Google Sheet.
2. В листе очереди (по умолчанию `Лист1`) добавляет ссылки в колонку `Ссылка`.
3. В листе `Управление` указывает:
   - **Цель по новым лидам**: `0` — не ограничивать число успешных лидов;
   - **Предел просмотра**: `0` — автоматически `2 × цель` (рекомендуется);
   - **Лист очереди**.
4. Ставит галочку **ЗАПУСТИТЬ В CRM**.
5. Ждёт смены статуса `ПРИНЯТО` → `РАБОТАЕТ`.

Галочка является явным разрешением live-записи в CRM. Диспетчер сразу снимает её,
создаёт уникальный `Команда ID` и не принимает вторую команду, пока первая не завершена.
Перед открытием обычного Chrome программа сверяет только активные строки
`crm_monitoring`; исторические `done` не обращаются к LPTracker. В этот момент
пульт показывает статус **`СИНХРОНИЗАЦИЯ CRM`** и небольшой счётчик в поле `Сообщение`;
`0 / цель` в поле лидов означает, что новые ссылки ещё не открывались, а не зависание.
Положительная цель считает именно новые лиды. При `0` worker идёт до конца всех
доступных строк и положенных повторов. Дубликаты, снятые объявления, страницы без
кнопки телефона и неоткрытые после всех попыток номера цель не расходуют, но входят
в предел просмотра, и не
считаются техническими ошибками.

После запуска поле **Сообщение**, лист **История запусков** и уведомления
показывают один компактный отчёт: обработано ссылок → открыто номеров → создано
лидов, причины неоткрытия, число решённых капч и понятный итог остановки.

Для первой дистанционной проверки задайте цель `1`. После результата `ЗАВЕРШЕНО`
проверьте одну карточку в CRM и запись в `История запусков`, затем увеличивайте лимит.

После первого прохода сверху вниз программа автоматически делает следующие
круги для строк, где кнопка телефона была, но номер ещё не открылся, и для
временных технических сбоев. Команда считается завершённой только после
исчерпания положенных попыток либо достижения положительной цели.

В начале live-команды проверяются только новые строки `crm_monitoring`, поэтому
историческая база не задерживает открытие Chromium. `Автоответчики` разрешает
один второй лид; после второго CRM ID строка больше не планируется.
`Недозвон` / `Не дозвон` завершает контроль без удаления карточки.

Новые ссылки идут раньше старых ошибок. Отложенная третья попытка получения
номера становится доступна через 30 минут и обрабатывается только после новых
ссылок. Live-запись выполняется исключительно в 10:00–19:45 местного времени.

## Очистка контрольных тестов

Для теста, после которого лиды не должны звонить, снача выполните безопасный просмотр:

```powershell
& ".\.venv\Scripts\python.exe" -m avito_crm cleanup-test-run --run-id RUN_ID
```

Команда покажет точные строки и CRM ID, но ничего не изменит. После сверки повторите её с
`--apply --expected-leads N`. Если CRM-монитор уже заменил Run ID строки, её можно указать точно через
`--row-id`. Удаляются только первые лиды указанных строк/запусков;
строки с повторным CRM ID блокируют автоочистку. После успеха строка становится `done`, поэтому
пульт не пытается повторно создать или синхронизировать удалённый лид.

## Аналитика

На листе `Аналитика` в ячейке **Период, дней** выберите 7, 30, 90 или 365.
Табло показывает текущий и предыдущий период одинаковой длины: запуски,
обработанные ссылки, попытки, открытые номера, созданные лиды, недоступные
объявления, неоткрытые номера, технические ошибки и конверсию. Нижний график
показывает дневную динамику. Данные обновляются из `История запусков` после
каждого production-запуска.

## Остановка

Поставьте галочку **Остановить**. Команда будет принята не позднее следующего опроса.
Если ещё идёт предварительная синхронизация CRM, она остановится между лидами и
Chromium не запустится. Если уже обрабатывается объявление, текущий безопасный шаг
завершится, после чего новая ссылка не откроется. Итоговый статус будет
`ОСТАНОВЛЕНО`. Аварийное завершение процесса через Task Manager не заменяет эту кнопку.

## Капча

Пульт не решает и не обходит CAPTCHA. При проверке Avito:

1. браузер остаётся открыт на удалённом компьютере;
2. очередь ставится на паузу;
3. работают уже настроенные MAX/email/Telegram-уведомления и напоминания;
4. ответственный заходит по RDP и вручную завершает проверку;
5. процесс сам продолжает текущую команду без отдельного сообщения
   «очередь продолжает работу».

Отдельной галочки для капчи нет. Программа ждёт без лимита по времени и после
ручного решения продолжает ту же строку. Если нужно отменить ожидание, оператор ставит
обычную галочку **Остановить**. Текущая строка не считается неудачной попыткой и будет доступна в
обычном следующем запуске.

Если один API временно недоступен, остальные каналы всё равно отправляются,
а сбойный канал повторяется на следующем напоминании. Ошибка одного адреса
внутри канала не отменяет успешную доставку остальным получателям.

## Где настраиваются уведомления

На Windows-ПК откройте ярлык **«Avito в CRM»** и строку
**«Капча и уведомления»**. В окнах MAX, Email и Telegram задаются основные и
резервные получатели, а также получатели итогового отчёта. Кнопка проверки
отправляет тестовое сообщение без запуска очереди. Настройки сохраняются только
в локальный `D:\avito-crm\.env`; контроллер перечитывает их перед каждой новой
командой, поэтому перезагрузка Windows и переустановка программы не нужны.

В Google-пульт нельзя переносить токены ботов, SMTP-пароль или другие секреты.
При необходимости туда можно отдельно вынести только получателей и флажки
доставки, но лист должен быть защищён от редактирования сотрудниками.

После полного завершения команды приходит одно сообщение со сводкой: сколько
ссылок обработано, номеров открыто, лидов создано, объявлений недоступно и
технических ошибок осталось.

## Сбои и защита от повторного запуска

- До запуска команда сохраняется локально в `data\remote-control.json` и получает
  уникальный ID.
- Одновременно разрешён только один диспетчер и один worker.
- После сбоя диспетчера/Windows незавершённая команда восстанавливается по ID и
  продолжает только недостающую часть положительной цели; в режиме `0` заново
  читает очередь и берёт только оставшиеся actionable-строки.
- Каждая строка очереди обновляется сразу после результата; прогресс не держится только
  в памяти.
- Если параллельно запущена очередь из GUI, пульт показывает `ОЖИДАЕТ` и начинает свою
  команду после освобождения worker.
- Если ссылки закончились раньше положительной цели, но все доступные строки получили
  нормальный результат, статус будет `ЗАВЕРШЕНО`; в сообщении останется фактическая
  фактическая статистика.

LPTracker дополнительно проверяется по телефону перед созданием. Как и для любой внешней
CRM, остаётся узкое аварийное окно: если компьютер выключится после успешного ответа CRM,
но до записи результата в Google, следующий запуск найдёт уже существующий телефон и не
создаст его второй раз. В истории такая строка может отобразиться как дубликат.

## Условия фоновой работы Windows

- Пользователь Windows должен оставаться **вошедшим** в систему.
- Окно RDP можно закрыть или выбрать «Отключиться».
- Нельзя выбирать «Выйти из системы»: видимый Chromium требует интерактивной сессии.
- После полного перезапуска Windows нужно один раз войти в эту учётную запись; затем
  задача стартует автоматически. Небезопасный автологин с сохранённым паролем намеренно
  не включается.

## Диагностика и отключение

Локальный журнал: `C:\avito-crm\logs\avito-crm.log`. Телефоны и токены в нём
маскируются. Состояние команды и lock-файлы находятся в игнорируемой Git папке `data`.

Отключить диспетчер, сохранив Google-листы и историю:

```powershell
.\scripts\uninstall-remote-control.ps1
```

Чтобы поменять имена листов или частоту опроса, используйте только
локальный `.env`:

```text
GOOGLE_CONTROL_WORKSHEET=Управление
GOOGLE_HISTORY_WORKSHEET=История запусков
REMOTE_CONTROL_POLL_SECONDS=20
```

После изменения перезапустите задачу через повторный вызов
`.\scripts\install-remote-control.ps1`.
