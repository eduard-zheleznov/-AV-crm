# Передача лида после звонка робота

Версия 1.12.12 добавляет отдельный идемпотентный обработчик лидов. По умолчанию
он выключен. Лид становится кандидатом только при одновременном выполнении двух
условий:

1. текущий шаг — `⚙️ Лид с робота`;
2. в категории `Тег+ для новых с Ав и Ян` выбрано одно из значений:
   `Сбор № лпр (Ав, ремонт кв. под ключ)` или
   `Сбор № лпр (Ян, ремонт кв. под ключ)`.

Поиск сначала проверяет краткие данные списка LPTracker. Полная карточка
запрашивается только для лида на шаге `⚙️ Лид с робота`, поэтому остальные
лиды не создают сотни лишних API-запросов. После загрузки полной карточки
проверяется один из двух разрешённых исходных тегов. Имя и техническое поле
источника не используются как триггер.
Список читается лениво страницами по 100 строк — это фактический лимит
LPTracker. После набора заданного числа подходящих лидов следующая страница не
запрашивается.
При точечной проверке `--lead-id` отчёт объясняет, почему лид
пропущен: не совпал шаг воронки или отсутствует подходящая запись звонка.
Если Direct API не включил запись в данные лида, обработчик читает ту же
защищённую ленту истории, которую показывает карточка LPTracker, и передаёт
авторизацию только домену LPTracker для скачивания аудио.

## Что делает обработчик

Для каждой карточки, прошедшей оба условия триггера:

1. проверяет шаг `⚙️ Лид с робота` и один из двух разрешённых исходных тегов;
2. выбирает последнюю успешную исходящую запись разговора;
3. передаёт аудио сервису распознавания и принимает только один однозначный
   российский номер;
4. заменяет единственное телефонное поле карточки новым номером;
5. перечитывает карточку и проверяет точное сохранение;
6. заменяет исходный тег в `Тег+ для новых с Ав и Ян` на
   `Предлагаем бесплатный аудит авито`;
7. устанавливает системное поле `Дата шага` (`funnel_date`) ровно на 48 часов
   вперёд по московскому времени и перечитывает карточку для проверки;
8. последним действием переводит карточку на шаг `Новый лид`.

Новый лид не создаётся. Если карточка имеет ноль или несколько телефонных полей,
запись содержит неоднозначный номер либо проверка не прошла, CRM не меняется без
подтверждённого безопасного шага, а ответственным отправляется уведомление.

## Защита от дублей и сбоев

- Каждый выполненный этап перечитывается из LPTracker.
- После частичного сбоя следующий запуск продолжает с незавершённого этапа.
- Если исходный тег уже заменён, продолжение разрешается только при совпадении
  локального журнала, записи звонка, распознанного номера и рассчитанной даты.
- Уже распознанная запись не отправляется в Gemini повторно.
- Рассчитанная `Дата шага` сохраняется в локальном журнале и не сдвигается, если
  повторный запуск произошёл после полуночи.
- После перехода на `Новый лид` карточка перестаёт быть кандидатом.
- Временная ошибка Gemini, сети или LPTracker повторяется автоматически.
- Неоднозначная запись блокируется до явного запуска с `--retry-analysis`.
- Список сканируется постранично, чтобы старые ожидающие лиды не потерялись за
  новыми.

## Выполнение на Mac

Если сервис распознавания отклоняет запросы с Windows-компьютера по его региону,
обработчик можно постоянно выполнять на Mac. Вычислительная мощность Windows-ПК
здесь ни при чём: ограничение относится к внешнему адресу запроса. Это не переносит на Mac загрузчик
Avito и не запускает браузер: Mac раз в две минуты обращается только к LPTracker,
скачивает запись подходящего звонка, распознаёт номер и выполняет уже описанную
идемпотентную последовательность изменений CRM.

Архитектура рассчитана на один активный применяющий обработчик:

- Windows-компьютер продолжает обслуживать Google-пульт и очередь Avito → CRM;
- Mac обслуживает только `Лид с робота`;
- после успешной проверки Mac флажок фоновой обработки на Windows выключается,
  чтобы два компьютера не меняли одну карточку одновременно;
- закрывать терминал и окно программы на Mac можно: LaunchAgent запускается при
  входе пользователя и автоматически восстанавливается после сбоя.

Настройки переносятся отдельным файлом с жёстким списком разрешённых параметров.
В него не попадают Google JSON, профиль Avito и ключ локального Chrome-моста.
Файл содержит секреты LPTracker и распознавания, поэтому его нельзя отправлять
в чат, облако или Git; после установки его следует удалить с Рабочего стола.

На Windows из корня проекта:

```powershell
& ".\scripts\export-mac-handoff-settings.ps1"
```

Перенесите папку `avito-mac-handoff` с Рабочего стола Windows на Рабочий стол
Mac через AnyDesk. На Mac из корня проекта:

```bash
bash scripts/install-mac-handoff-worker.sh --settings "$HOME/Desktop/avito-mac-handoff/handoff.env"
```

Проверка состояния:

```bash
bash scripts/mac-handoff-status.sh
```

После подтверждённого запуска удалите перенесённую папку с обоих Рабочих столов.
Локальная рабочая копия настроек хранится с правами `600` в
`~/Library/Application Support/AvitoCRM-Handoff/.env`.

Mac должен быть включён, пользователь должен оставаться вошедшим в систему, а
ноутбук не должен спать с закрытой крышкой. LaunchAgent предотвращает обычный
бездействующий сон при открытой крышке; сам worker работает с низким приоритетом
и не мешает обычной работе.

## Секрет и включение на Windows

Ключ распознавания вводится только локально на Windows-компьютере в скрытое поле
`Ключ распознавания` ярлыка **Avito в CRM**. Не отправляйте ключ в чат, Google Sheets,
журналы или Git.

Сначала сохраните ключ, оставив флажок `Обрабатывать «Лид с робота»` выключенным.
Контроллер перечитывает локальный `.env`, поэтому после сохранения перезапуск
Windows не требуется.

## Контролируемая проверка

Команды выполняются в PowerShell из `D:\avito-crm`. Предварительный режим
скачивает и распознаёт запись, но не меняет LPTracker:

```powershell
& ".\.venv\Scripts\python.exe" -m avito_crm robot-handoff --lead-id 123456789
```

После ручной сверки одного заранее выбранного лида:

```powershell
& ".\.venv\Scripts\python.exe" -m avito_crm robot-handoff --lead-id 123456789 --apply
```

Проверьте в LPTracker:

- старый временный телефон заменён, второго телефона нет;
- установлен нужный тег;
- `Дата шага` равна текущему московскому времени плюс 48 часов;
- шаг стал `Новый лид`;
- повтор той же команды ничего не меняет.

После успешной проверки один раз установите в GUI флажок
`Фоновая обработка «Лид с робота»`. Выбор сразу сохраняется локально,
не требует нажатия «Проверить доступ» и не сбрасывается при закрытии GUI или
обычном обновлении. Фоновый контроллер проверяет
новые карточки каждые 120 секунд небольшими пакетами и не мешает основной очереди.

## Ручная проверка

После исправления причины можно повторить анализ одной карточки:

```powershell
& ".\.venv\Scripts\python.exe" -m avito_crm robot-handoff --lead-id 123456789 --retry-analysis
```

Добавьте `--apply` только после проверки причины и карточки. Телефон, аудио и текст
разговора не печатаются в консоль и не включаются в уведомления.
