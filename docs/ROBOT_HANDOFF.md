# Передача лида после звонка робота

Версия 1.12.3 добавляет отдельный идемпотентный обработчик лидов на шаге
`⚙️ Лид с робота`. По умолчанию он выключен.

## Что делает обработчик

Для каждого лида, созданного Avito CRM Pipeline:

1. проверяет, что карточка всё ещё находится на шаге `⚙️ Лид с робота`;
2. выбирает последнюю успешную исходящую запись разговора;
3. отправляет аудио в Gemini и принимает только один однозначный российский номер;
4. заменяет единственное телефонное поле карточки новым номером;
5. перечитывает карточку и проверяет точное сохранение;
6. устанавливает `Тег+ для новых с Ав и Ян` =
   `Предлагаем бесплатный аудит авито`;
7. устанавливает системное поле `Дата шага` (`funnel_date`) ровно на 48 часов
   вперёд по московскому времени и перечитывает карточку для проверки;
8. последним действием переводит карточку на шаг `Новый лид`.

Новый лид не создаётся. Если карточка имеет ноль или несколько телефонных полей,
запись содержит неоднозначный номер либо проверка не прошла, CRM не меняется без
подтверждённого безопасного шага, а ответственным отправляется уведомление.

## Защита от дублей и сбоев

- Каждый выполненный этап перечитывается из LPTracker.
- После частичного сбоя следующий запуск продолжает с незавершённого этапа.
- Уже распознанная запись не отправляется в Gemini повторно.
- Рассчитанная `Дата шага` сохраняется в локальном журнале и не сдвигается, если
  повторный запуск произошёл после полуночи.
- После перехода на `Новый лид` карточка перестаёт быть кандидатом.
- Временная ошибка Gemini, сети или LPTracker повторяется автоматически.
- Неоднозначная запись блокируется до явного запуска с `--retry-analysis`.
- Список сканируется постранично, чтобы старые ожидающие лиды не потерялись за
  новыми.

## Секрет и включение

Ключ Gemini вводится только локально на Windows-компьютере в скрытое поле
`Ключ распознавания` ярлыка **Avito в CRM**. Не отправляйте ключ в чат, Google Sheets,
журналы или Git.

Сначала сохраните ключ, оставив флажок `Обрабатывать «Лид с робота»` выключенным.
Контроллер перечитывает локальный `.env`, поэтому после сохранения перезапуск
Windows не требуется.

## Контролируемая проверка

Команды выполняются в PowerShell из `D:\avito-crm`. Предварительный режим
скачивает и распознаёт запись, но не меняет LPTracker:

```powershell
& ".\.venv\Scripts\python.exe" -m avito_crm robot-handoff --lead-id 123456789
```

После ручной сверки одного заранее выбранного лида:

```powershell
& ".\.venv\Scripts\python.exe" -m avito_crm robot-handoff --lead-id 123456789 --apply
```

Проверьте в LPTracker:

- старый временный телефон заменён, второго телефона нет;
- установлен нужный тег;
- `Дата шага` равна текущему московскому времени плюс 48 часов;
- шаг стал `Новый лид`;
- повтор той же команды ничего не меняет.

После успешной проверки установите в GUI флажок
`Обрабатывать «Лид с робота»` и сохраните настройки. Фоновый контроллер проверяет
новые карточки каждые 120 секунд небольшими пакетами и не мешает основной очереди.

## Ручная проверка

После исправления причины можно повторить анализ одной карточки:

```powershell
& ".\.venv\Scripts\python.exe" -m avito_crm robot-handoff --lead-id 123456789 --retry-analysis
```

Добавьте `--apply` только после проверки причины и карточки. Телефон, аудио и текст
разговора не печатаются в консоль и не включаются в уведомления.
