# Эксплуатация

## Рекомендуемый процесс

Для работы без RDP используйте [удалённый Google Sheets-пульт](REMOTE_CONTROL.md):
сотрудник добавляет ссылки, задаёт цель и предел просмотра, затем ставит галочку запуска.
Значение `0` для предела ссылок означает «без отдельного ограничения»: программа идёт до
достижения цели по созданным лидам либо до конца доступной очереди. Ниже остаётся
локальный процесс через GUI.

1. Добавьте ссылки в Google Sheet.
2. Откройте ярлык **«Avito в CRM»**. При необходимости кнопкой **«Открыть профиль»**
   войдите в Avito, выйдите из аккаунта или оставьте гостевой режим, затем закройте браузер.
3. Укажите цель либо `0` для всей очереди и нажмите **«Запустить в CRM»**.
4. Следите за видимым Playwright-браузером; при проверке Avito завершите её вручную.
5. Посмотрите `status.ps1` и отфильтруйте технический `error` либо строки,
   ожидающие ручной проверки.
6. После исправления внешней причины повторите запуск. Для ручных строк добавьте
   `-RetryManual`.

## Остановка и продолжение

GUI-кнопка **«Остановить»** (или `stop.ps1` для терминального режима) создаёт локальный stop-флаг. Worker завершит текущий безопасный шаг и
не возьмёт новую строку. При следующем запуске флаг автоматически очищается.
Ctrl+C также поддерживается.

В удалённом режиме мягкая остановка доступна галочкой **Остановить** на листе
`Управление`. Не запускайте GUI-очередь одновременно: пульт безопасно дождётся
освобождения worker, но два разных оператора получат менее очевидный порядок задач.
До открытия браузера пульт может кратко показывать `СИНХРОНИЗАЦИЯ CRM`: это
проверка только активных новых лидов `crm_monitoring`. Исторические `done` не
проверяются. Текущий счётчик показывается в сообщении пульта; остановка
проверяется между CRM-лидами.

Новые строки обрабатываются раньше `retry_phone` и `retry_technical`. Финальная
попытка номера становится доступна через 30 минут, поэтому может перейти в
следующий запуск. Если компьютер выключился на статусе `processing`, новый запуск
безопасно восстановит строку.
Локальный SQLite-журнал восстанавливает `done` даже если CRM успела ответить, а
таблица не успела сохраниться. Дополнительно CRM проверяется по телефону до записи.

## Результаты и ошибки

- `inactive`: Avito явно сообщил, что объявление снято, закрыто, удалено или
  заблокировано; это нормальный конечный результат;
- `unavailable`: страница открылась, но кнопки телефона нет; это нормальный
  конечный результат;
- `no_phone`: кнопка была, однако номер не открылся после всех попыток; это
  нормальный конечный результат;
- `retry_phone`: кнопка была, номер пока не открылся; программа повторит строку
  в следующем круге этого же запуска;
- `retry_technical`: временная техническая проблема; программа повторит строку;
- `error`: техническая проблема сохранилась после исчерпания попыток;
- `OCR ...`: проверьте диагностический PNG в `output\diagnostics`;
- капча: решите её в открытом Chrome; та же строка продолжится автоматически; для отмены нажмите
  **Остановить**, и строка будет сохранена для обычного следующего запуска;
- `LPTracker 401`: проверьте логин/пароль; токен обновляется автоматически;
- `LPTracker 503`: превышен лимит или сервис временно недоступен; есть retry с
  backoff, а частота дополнительно ограничена до 2 запросов/сек;
- пять последовательных технических ошибок: срабатывает аварийная остановка, чтобы не портить
  очередь и не нагружать Avito/CRM.

Неактивные объявления, отсутствие кнопки и исчерпанные попытки открытия номера
не переводят весь запуск в состояние «с техническими ошибками». После завершения
приходит одно итоговое уведомление со статистикой. Отдельное уведомление
«проверка завершена, очередь продолжает работу» намеренно не отправляется.

## Политика повторных лидов

По умолчанию `CRM_DUPLICATE_POLICY=skip`. Тот же Avito ID никогда не создаётся
повторно: при повторном запуске восстанавливается его CRM ID. Другое объявление с
тем же номером пропускается только если самому свежему CRM-лиду по этому номеру
менее `CRM_DUPLICATE_WINDOW_DAYS` дней (по умолчанию 7). При возрасте 7 дней или больше создаётся
новый лид для нового объявления. Если дату лида определить нельзя, действует безопасный
пропуск. `CRM_DUPLICATE_POLICY=create_lead` по-прежнему полностью отключает временное окно.

CRM проверяется только у новых строк со статусом `crm_monitoring`. Исторические
`done` не синхронизируются. `Автоответчики` разрешает один повторный лид на шаге
`Повторный лид`; после счётчика `2` строка терминальна независимо от дальнейшего
шага второго лида.

`Недозвон` / `Не дозвон` завершает контроль без удаления карточки. Правило
удаления по задержке больше 10 минут отключено. Перед каждым созданием CRM-лида
обязательна проверка местного окна 10:00–19:45 по `Δ к МСК` из листа
`План загрузки`.

Имя нового лида начинается с разницы во времени с Москвой без знака:
`2 Авито — 123456789`. Москва, Калининград и любое неположительное значение
получают префикс `0`. Старые имена без префикса по-прежнему распознаются.

Новые ссылки имеют приоритет над старыми `retry_phone`. Для каждого цикла звонка
разрешены два клика получения номера в первой сессии и один финальный клик не
раньше чем через 30 минут. После третьего неуспешного клика строка терминальна.

## Передача лида после звонка робота

Обработчик сочетания шага `⚙️ Лид с робота` и утверждённого тега сбора выключен
по умолчанию. Его отдельная безопасная
настройка, предварительная проверка и включение описаны в
[ROBOT_HANDOFF.md](ROBOT_HANDOFF.md). Он не создаёт новый лид: заменяет единственный
временный телефон, проверяет сохранение, ставит тег и только затем переводит
карточку на шаг `Новый лид`.

## Обновление селекторов

Avito может менять DOM. Браузерный код намеренно использует несколько семантических
локаторов, а не один CSS-класс. При устойчивой ошибке сохраните диагностический
скриншот и обновляйте только `src/avito_crm/avito.py`, не меняя очередь/CRM.
