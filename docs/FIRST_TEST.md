# Первая фактическая проверка — без догадок

Для первого теста рекомендуется локальный Excel с одной рабочей ссылкой
Avito. Это проверит весь поток без отдельной настройки Google API.

## Что подготовить один раз

1. На удалённом Windows-компьютере откройте PowerShell в папке проекта.
2. Выполните установку:

   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\scripts\install.ps1
   ```

3. Откройте локальный `.env` и заполните:

   - `LPTRACKER_LOGIN` и новый пароль;
   - `TESSERACT_CMD`, если установщик его не нашёл.

   `LPTRACKER_PROJECT_ID` пока можно оставить пустым: мастер сначала покажет все
   доступные проекты и даст паузу, чтобы вставить нужный ID в `.env`.

4. Откройте созданный установщиком `queue-template.xlsx`, вставьте одну
   ссылку под заголовок `Ссылка`, сохраните и **закройте Excel**. Иначе Excel
   может заблокировать файл для записи статусов.

## Запуск мастера

Рекомендуемый первый запус через Excel:

```powershell
.\scripts\first-test.ps1 `
  -Source xlsx `
  -File ".\queue-template.xlsx" `
  -Sheet "Лист1"
```

После него можно отдельно проверить Google Sheets:

```powershell
.\scripts\first-test.ps1 -Source google -Sheet "Тест"
```

## Что произойдёт

### Шаг 1 — окружение

Ожидаются строки `OK Tesseract OCR`, `OK Chromium` и `OK Очередь`. CRM не
изменяется.

### Шаг 2 — CRM без записи

Мастер выведет список `ID — название проекта`. Скопируйте нужный ID в
`LPTRACKER_PROJECT_ID` файла `.env`, сохраните файл и нажмите Enter. Затем
проверяются точное поле и настроенное значение. LPTracker может не вернуть список
вариантов поля-категории; в этом случае значение дополнительно сверяется на одном
тестовом лиде. До отдельного подтверждения лиды не создаются.

### Шаг 3 — один номер

Откроется видимый Chromium. Если Avito попросит вход или проверку, завершите её
вручную. Система откроет телефон и напечатает распознанный номер, не закрывая
страницу. Сравните цифры на странице и в консоли:

- совпали — введите `ДА`;
- не совпали — введите что угодно другое: номер не будет сохранён, CRM не
  изменится, строка получит понятную ошибку.

После `ДА` в таблице должны появиться `captured`, телефон, время и Run ID.

### Шаг 4 — ровно один лид

Мастер попросит точную фразу `СОЗДАТЬ 1 ЛИД`. Только после неё уже распознанный
номер передаётся в LPTracker. Avito второй раз не открывается.
Если телефон уже есть в CRM, мастер безопасно остановится с результатом `duplicate`
и не будет утверждать, что тестовый лид создан.

### Шаг 5 — ручная сверка CRM

Откройте созданный лид и проверьте:

1. телефон полностью совпадает;
2. название начинается с `Авито —`;
3. поле `Тег+ для новых с Ав и Ян` содержит
   `Сбор № лпр (Ав, ремонт кв. под ключ)`;
4. в таблице стоит `done` и заполнен `CRM lead ID`.
5. в «Продажи (комментарии)» записана ссылка Avito.

Если все пять пунктов верны, выполните полный тест на 3 лида, затем на 10:

```powershell
.\scripts\run.ps1 -Source google -Sheet "Тест" -Limit 3 -Mode full -Live
.\scripts\run.ps1 -Source google -Sheet "Рабочий лист" -Limit 10 -Mode full -Live
```

## Повторные лиды

Обычный первый лид по-прежнему защищён `CRM_DUPLICATE_POLICY=skip`.
Исключение управляется строкой: если её первый `CRM lead ID` перешёл на шаг
`Автоответчик`, следующий live-запуск повторно откроет этот URL и создаст
второй лид на шаге `Повторный лид`. После успеха счётчик равен `2`, и новых
повторов не будет. На тесте проверьте оба ID и точный шаг второго лида.
